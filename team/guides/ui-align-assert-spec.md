# UI Structural Assertion Spec (machine-checkable gate)

> Ownership: `PROTOCOL §⑨.1` (UI fidelity: prototype is the contract) and `§⑳.1` (machine-checkable gates).
> Applies to: the "during structural assertions" and "post-acceptance re-run" of all UI cards.

## 1. Artifact Contract

Each UI card's workspace produces two files (path `workspace/<task-id>/`):

- `ui-selectors.json` — the **selector manifest** (block enumeration), structured as:
  ```json
  {
    "page": "<page identifier>",
    "viewports": ["1512", "1240", "980", "760", "430"],
    "blocks": [
      { "name": "top nav", "selector": "[data-nav-topbar]", "required": true },
      { "name": "KPI card group", "selector": "[data-ov-kpi] .kpi-card", "required": true, "min": 3 }
    ],
    "noHorizontalOverflow": { "viewports": ["1512","1240","980","760","430"] }
  }
  ```
  Conventions: prefer `data-*` semantic hooks for selectors (do not depend on Tailwind class names); the **list must include "consistent" items** (to prevent omissions).

- `ui-check.mjs` (or an equivalent runner) — reads `ui-selectors.json` and asserts in a headless browser:
  1. every `required` selector exists and is visible;
  2. the `min` count is met;
  3. at each viewport `document.scrollingElement.scrollWidth <= clientWidth` (no horizontal overflow);
  4. `console/pageerror` is empty.

## 2. Determination

- All assertions pass ⇒ the card's UI structural gate passes (Linus must run it before delivery; Turing re-runs it at acceptance).
- Any assertion fails ⇒ the card must not be set to `in_review`/`done`.
- **Screenshot comparison** (same viewport × same theme × same language) remains **manual/semi-automatic**: batches of screenshots may be pre-generated by script, but the final comparison is still personally verified by Elon (§⑨.1 hard gate #4).

## 3. Relationship to the Line-Number Ban

The selector manifest writes only **block names / `data-*` / selectors**, with **no line-number anchors** (following `§⑥.1 clause 11`).
