## 0. 目的与总原则

- **目的**：显式划定「设计资产（Jobs）」与「推广素材（Assistant）」的归属边界与交接形态；统一「设计交付物」的定义、载体与审核门禁。
- **总原则**：
  1. **Jobs = 审美与设计风格唯一裁决者**（五项职责 + 风格主权）。凡**品牌视觉 / 界面视觉 / 交互 / 设计规范 / 视觉资产** ⇒ 归 **Jobs**。
  2. **Assistant = 推广 / 运营 / 客服 执行**。推广物料在其职责内，但**其视觉必须遵循 Jobs 的统一风格规范**（色板/字体/token），**不得自定设计风格**。
  3. **一句话分界**：**定义「长什么样、为什么这样」= Jobs；把「已定义的样子」铺到推广渠道 = Assistant。**
  4. **越界不可静默**：发现另一角色领域的需求 ⇒ 回发 Elon 建卡（worker 不互派单，`§⑩`）。

## 1. Jobs 行边界表（做 / 不做 / 交接 / 关键产出）

> 供 Elon 并入 `ROLES.md` **Jobs 行**；三列（做/不做/交接）不得为空。

| 角色 | 做（范围） | 不做（排除） | 关键输入 | 关键产出 | 交接对象 |
|---|---|---|---|---|---|
| **Jobs** | ① 产品设计（产品方案/需求分析/信息架构/交互流程）② PRD 文档（需求文档/功能规格/验收标准）③ UI 设计（界面视觉/色彩/字体/组件库/设计规范）④ UX 设计（体验/交互/可用性/设计走查）⑤ **图片设计**（插画/Logo/海报/主视觉，经 `canvas-design`）+ **审美与设计风格主权**（定位/选择/统一，唯一裁决者）+ UX/UI `review_of` 评审 | 后端与业务代码 / 功能测试执行 / 量化研究 / **推广物料制作与投放**（归 Assistant）/ **推广文案撰写**（归 Assistant，界面 UI 文案除外） | 卡(设计) + 已定统一风格规范 + 上游 PRD/需求 | **设计交付物**（见 §2）：PRD / 方案 / `DESIGN.md` / `design-style-guide.md` / 原型(HTML 或 Pixso) / 图片(.png·.pdf) / 《问题清单》 | Linus（实现基线契约）/ Elon（产品设计文档双签 §⑭）/ Assistant（品牌视觉资产） |

**界定要点（Jobs）**：
- Jobs 的「做」以**设计定义与视觉资产**为界，**不含**把设计物投放到推广渠道（投放/运营/客服属 Assistant）。
- 「界面 UI 文案」= Jobs（属 UI/UX 设计）；「推广/营销文案」= Assistant（属推广素材）。
- 画像/插画/Logo/海报/主视觉等**静态视觉资产的创作归 Jobs**；推广场景下的**物料复用与排版投放归 Assistant**（复用须符合 Jobs 规范）。

## 2. 设计交付物定义统一（载体 + 产出方式 + 审核门禁）

> 统一「设计交付物」= **Jobs 五项职责**的最终产物；均落任务工作区 `workspace/<task-id>/`（L5），按 `§⑥` 载体分流产出。

| # | 交付物 | 载体 / 形态 | 产出方式（工具链，`§⑥`） | 审核门禁 |
|---|---|---|---|---|
| 1 | **PRD / 需求文档 / 功能规格** | Markdown（`workspace/<task-id>/`） | **Claude Code 子会话**产出（Jobs 主导规划 → 子会话撰写） | **Elon 审议双签 `§⑭`**（产品设计文档终稿） |
| 2 | **产品方案 / 设计提案** | Markdown | 同 #1（Jobs 主导规划 + Claude Code） | 含产品设计文档性质 ⇒ `§⑭` 双签；纯方向提案 ⇒ Elon 拍板 |
| 3 | **`DESIGN.md` / 设计规范 / `design-style-guide.md`** | Markdown | Claude Code 子会话（或 Pixso 载体）；Jobs 裁决 | Jobs 自审 + **跨页/跨任务风格一致性**比对（`roles/jobs/AGENTS.md` 第 9 条） |
| 4 | **可运行原型（HTML 高保真）** | HTML/CSS/JS（**技术栈封闭 = Tailwind CSS + daisyUI + jQuery；3D 例外 three.js**） | ① Jobs 出 `design-spec.md`（详细设计需求规范）→ ② **Claude Code 子会话**编码（只代码、不设计）→ ③ Jobs 验证审核 | **Jobs 按 `design-spec` 逐条比对 + `§⑨.1` 结构契约/截图对照**；不达标回退 |
| 5 | **可运行原型（Pixso 载体）** | Pixso 文件 / 导出文件 | **Jobs 直接经 Pixso MCP + `pixso-*` skills**（不 spawn Claude Code） | Jobs review；交付物含 **pixso 链接或导出文件** |
| 6 | **图片（插画 / Logo / 海报 / 主视觉）** | `.png` / `.pdf` + 设计哲学 `.md` | ① Jobs 出 `image-brief.md`（视觉设计简令）→ ② **Claude Code 子会话用 `canvas-design` skill**（先写设计哲学 md → 再出 png/pdf）→ ③ Jobs 审核 | Jobs 审核是否符合 `image-brief` + 项目视觉规范；不符打回子会话修订 |
| 7 | **《问题清单》（UX/UI review）** | Markdown（`workspace/<task-id>/review/`） | Jobs **亲自**（浏览器/工具交互认证：截图/点击流/关键状态） | 回填目标卡；无未决项方可放行（`§⑨` 尾节 产品/UX 验收触发） |

**统一口径**：
- **载体二分**：设计物只在 **Pixso 载体** 与 **HTML 载体** 二者择一（图片设计另走 `canvas-design`）；**Jobs 不直写 HTML/CSS/JS，不直出图**（`§⑥` 强制红线）。
- **审核门禁二分**：**产品设计文档（#1/#2）⇒ `§⑭` 双签**；**原型/图片（#4–#6）⇒ Jobs 自审 + 规范/契约比对**。
- **单一风格源**：所有交付物共用**统一设计风格规范**（色板/字体/间距/圆角/组件态/动效 token），风格变更须**显式声明 + 同步受影响产物**（`roles/jobs/AGENTS.md` 第 9 条）。

## 3. 与 Assistant 的交接点（设计图 vs 推广素材 / 品牌视觉 vs 推广视觉）

> 供 Elon 并入 `ROLES.md` **Jobs 行与 Assistant 行的「行间边界」**。

### 3.1 边界矩阵

| 类别 | 归属 | 说明 |
|---|---|---|
| **品牌视觉**（Logo / VI / 色板 / 字体 / 主视觉 / 品牌 token） | **Jobs** | 定义与创作归 Jobs；**唯一裁决者**，含变更审批 |
| **界面视觉**（产品 UI 稿 / 原型 / 设计规范 / 组件态） | **Jobs** | 实现基线契约（`§⑨.1`） |
| **插画 / 海报 / 主视觉（静态图创作）** | **Jobs** | 经 `canvas-design` 出图 |
| **推广视觉物料**（投放 banner / 社媒图 / 落地页物料 / 活动图） | **Assistant** | 制作与投放归 Assistant；**视觉须遵循 Jobs 品牌规范** |
| **推广文案 / 营销文案 / 社媒文案** | **Assistant** | copywriting 在其职责内 |
| **界面 UI 文案**（产品内文案） | **Jobs** | 属 UI/UX 设计范畴 |
| **推广效果度量 / 投放台账 / 客服知识库** | **Assistant** | 见 `promo-ops-sop.md` / `ops-ledger-spec.md` / `cs-playbook.md` |

### 3.2 交接点（Handoff）

| 方向 | 交接物 | 形态 | 规则 |
|---|---|---|---|
| **Jobs → Assistant** | 品牌视觉资产包 | `design-style-guide.md` + 源文件（Logo/色板/字体/主视觉导出） | Assistant 据此制作推广物料，**不得改规范**；缺失资产 ⇒ 回发 Elon 建 Jobs 卡 |
| **Assistant → Jobs** | 推广视觉需求 | 需求描述（用途/尺寸/渠道/调性） | 需**新设计资产/风格变更** ⇒ 回发 Elon 建 Jobs 卡；Jobs 不直收（worker 不互派单 `§⑩`） |
| **Jobs → Linus** | 原型 / `DESIGN.md` | HTML 构建产物 / Pixso 导出 / md | 作为**实现基线契约**（`§⑨.1`）；偏离须书面说明并经 Elon 批准 |
| **Jobs → Elon** | 产品设计文档终稿 | PRD/方案 md | **`§⑭` 双签**后方可作下游依据 |

### 3.3 争议/变更裁决
- **审美与风格争议**：Jobs 为**唯一裁决者**；Assistant 认为规范不适配推广场景 ⇒ 提需求，**不自行改风格**。
- **品牌重大变更**（Logo/VI/主视觉更换）：Jobs 定义 + 影响重大/有分歧时**带推荐回发 Elon 拍板**。
